# 前端页面重设计方案

日期：2026-07-05

## 1. 背景与目标

当前前端已经完成 Vue MVP、真实后端接口接入、Dashboard + 模块侧边栏布局改造，但用户反馈页面仍然存在两个核心问题：

1. 页面“框框”较乱，视觉不够整齐。
2. 功能入口和操作容易堆在主页面上，缺少清晰的信息分层。

本次重设计目标是：

- 让首页只承担概览和入口职责，不堆复杂功能。
- 让每个功能页用自己的侧边栏承载当前模块的筛选、会话或关键动作。
- 让问答页接近主流网页 AI 产品的会话体验。
- 保持简洁浅色 Dashboard 风格，减少装饰性视觉，优先提升整齐度、可读性和操作路径清晰度。

## 2. 已确认的设计选择

### 2.1 整体布局

采用“主页面顶部导航 + 功能页模块侧边栏”的混合布局：

- 顶部导航作为全局模块入口，包含：首页、文献、问答、想法。
- 功能页内部再根据模块需要展示侧边栏。
- 不采用全局左侧菜单，避免进入问答页后出现“全局左栏 + 会话左栏”的双左栏问题。

### 2.2 视觉风格

采用“简洁浅色 Dashboard”风格：

- 背景使用浅灰蓝或接近白色的低对比背景。
- 卡片边框和阴影轻量化，避免厚重的框线。
- 主色继续使用蓝色系，用于当前导航、主按钮、选中状态。
- 少量保留论文研究语义，例如引用片段、研究想法、空状态文案，但不做大面积纸张纹理或深色 AI Lab 风。

### 2.3 首页内容

首页选择“概览 + 最近活动”：

- 展示核心统计，例如文献总数、已解析、已向量化、历史会话、研究想法数量。
- 展示最近会话和最近研究想法。
- 提供进入文献、问答、想法模块的轻量按钮。
- 不在首页放上传表单、完整文献表格、复杂问答框或 Research Idea 编辑表单。

### 2.4 功能页侧边栏密度

功能页侧边栏选择“平衡型侧边栏”：

- 每个模块保留 3-5 个常用筛选或入口。
- 每个模块最多放 1-2 个主要动作。
- 避免把全部操作按钮塞进侧边栏，防止页面再次变乱。

## 3. 页面结构设计

### 3.1 全局 App 外壳

全局外壳由顶部导航和页面主体组成：

```text
顶部导航：Research Desk / 首页 / 文献 / 问答 / 想法
页面主体：当前路由页面
```

顶部导航需要：

- 明确显示当前模块选中状态。
- 保持高度稳定，不随页面内容变化。
- 不承载具体业务筛选，业务筛选放到对应功能页。

### 3.2 首页 Dashboard

首页结构：

```text
页面标题区
核心统计卡片区
最近会话列表
最近研究想法列表
轻量模块入口
```

首页只回答“现在系统里有什么”和“下一步去哪里”，不承担具体业务操作。

### 3.3 文献页

文献页结构：

```text
左侧文献侧边栏
- 全部文献
- 待解析
- 待向量化
- 已向量化
- 上传文献
- 刷新

右侧主内容
- 文献列表
- 文献状态
- 解析 / 向量化 / 问答等行内操作
- 上传文献弹窗
```

设计原则：

- 文献上传继续使用弹窗入口，不直接堆在列表上方。
- 筛选入口放侧边栏，列表区域专注展示文献。
- 解析、向量化、问答这些与单篇文献强相关的操作保留在表格行内。

### 3.4 问答页

问答页按主流网页 AI 产品形态设计：

```text
左侧会话栏
- + 新建会话
- 所有会话标题列表

中间聊天区
- 当前会话标题
- 会话消息
- 输入框
- 保存 Research Idea 操作

右侧上下文区
- 默认隐藏或按需打开
- 选择参考论文
- 展示本轮引用片段
- 展示模型 / 检索辅助信息
```

关键交互：

1. 左侧栏直接显示所有会话标题，不再只显示“当前会话 / 最近会话”这样的抽象入口。
2. 新建会话入口放在左侧栏顶部。
3. 保存 Research Idea 不放在左侧栏，而放在当前会话页面内：
   - 主入口放在当前会话标题右侧的操作区，作为“保存想法”按钮。
   - 当 assistant 回答返回 `suggestSaveAsIdea` 时，在该回答下方显示轻量提示和“保存为想法”按钮。
4. 右侧上下文区默认不常驻占位。用户需要选择参考论文或查看引用片段时再展开。
5. 参考论文选择采用默认多选交互：右侧展示所有可选论文，用户点击几篇就选中几篇，再点击已选论文可取消选择，不额外提供“单选/多选模式”切换。
6. 选中的论文作为当前会话的参考范围，用于后续 RAG 问答。

问答页优先推荐的布局状态：

```text
默认状态：左侧会话栏 + 中间聊天区
需要上下文时：左侧会话栏 + 中间聊天区 + 右侧上下文区
```

### 3.5 Research Idea 页

Research Idea 页结构：

```text
左侧想法侧边栏
- 状态统计
- 关键词搜索
- 全部 / 草稿 / 想法 / 待办 / 已完成
- 刷新

右侧主内容
- 想法列表
- 状态流转
- 查看详情
- 删除
```

设计原则：

- 状态筛选和统计放在侧边栏。
- 想法内容、状态推进和详情查看放在主内容区。
- 不在首页堆 Research Idea 的编辑或详情能力。

## 4. 数据与状态流

### 4.1 首页数据

首页继续复用现有 API：

- 文献列表接口用于统计文献总数、解析数、向量化数。
- 会话列表接口用于展示最近会话。
- Research Idea 列表和统计接口用于展示最近想法和状态数量。

### 4.2 问答页数据

问答页需要继续复用现有会话和 RAG API，并为“参考论文选择”预留前端状态：

- 左侧会话列表加载所有会话标题。
- 点击会话后加载当前会话消息。
- 新建会话时清空当前消息，准备选择参考论文或直接提问。
- 右侧论文多选状态保存在当前页面状态中。
- 发送问题时，本阶段先复用现有 RAG API，不新增后端接口；前端保留选中论文状态并在界面上展示当前参考范围，后续如需让检索严格限定论文范围，再单独扩展 RAG API 参数（例如 selectedPaperIds）和后端过滤逻辑。

## 5. 错误处理与空状态

- 首页数据加载失败时，显示轻量错误提示，并允许刷新。
- 文献页为空时，主区域展示“暂无文献，先上传 PDF”。
- 问答页无会话时，左侧展示新建会话入口，中间展示提问引导。
- 参考论文列表为空时，右侧上下文区提示“暂无可选文献，请先上传并向量化论文”。
- Research Idea 为空时，提示用户可从问答页保存研究想法。

## 6. 验证重点

实现后需要重点验证：

1. 首页不再出现复杂表格或表单，只展示概览和最近活动。
2. 顶部导航在各页面选中状态正确。
3. 文献页、问答页、想法页都使用模块侧边栏，且侧边栏信息不过密。
4. 问答页左侧可以看到会话标题列表，并可新建会话。
5. 问答页保存 Research Idea 的入口位于当前会话内容区，不在左侧栏。
6. 右侧上下文区按需打开，参考论文支持点击多选。
7. 构建命令 `npm run build` 通过。
8. 现有 API helper 测试继续通过。

## 7. 非目标

本次重设计不包含：

- 新增后端接口。
- 改造 RAG 检索逻辑。
- 改造数据库表结构。
- 实现复杂拖拽布局或用户自定义主题。
- 一次性加入批量文献处理等高密度管理功能。

如果后续要让 RAG 严格限定在用户选择的论文范围内，应单独设计后端 API 参数和检索过滤逻辑。
