# 历史感知多轮 RAG 计划

> 状态：已完成
> 日期：2026-07-16

## 目标

让同一会话中的省略、指代和比较型追问能够结合最近对话，改写为可独立检索的问题，再复用现有 RAG 链路回答。

## 实施范围

- 读取当前会话最近 3 轮消息，限制单条和总字符数；
- 通过轻量规则判断问题是否需要历史，明确包含论文 ID/标题的问题不额外改写；
- 仅对“它、该方法、上述、相比、还有呢”等依赖历史的问题调用模型改写；
- 检索和 Prompt 使用独立问题，历史中仍保存用户原始问题；
- 同步和 SSE 响应都返回 `retrievalQuestion`，前端执行详情展示原问题与实际检索问题；
- 建立连续追问用例，比较目标论文、关键词和改写正确性。

## 边界

- 不新增长期记忆、向量化对话历史或用户画像；
- 不改变现有文献路由、召回排序和模型回答参数；
- 新会话和完整独立问题不增加模型调用；
- 历史读取失败或模型改写失败时回退到原始问题，不阻断 RAG。

## 验收标准

1. 无会话或独立问题保持原问题；
2. 指代型追问能生成包含目标论文/方法的独立问题；
3. 同步与 SSE 都返回并展示实际检索问题；
4. 原问题保存到历史，回答和检索使用改写问题；
5. 原有前后端测试保持通过；
6. 真实连续追问形成量化报告并独立提交 Git。

## 完成结论

- 后端已实现最近 6 条消息的按需追问改写，并提供读取/模型失败回退；
- 检索和回答使用独立问题，历史记录保留用户原始输入；
- 同步响应与 SSE 元数据返回 `retrievalQuestion`，前端只在发生改写时展示差异；
- 后端全量 143 项测试无失败，前端 58/58 测试和生产构建通过；
- 三类真实连续追问的改写锚点、策略和预期论文召回均为 100%。
