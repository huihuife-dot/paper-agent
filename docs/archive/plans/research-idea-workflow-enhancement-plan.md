# Research Idea 工作流增强计划

> 计划日期：2026-07-16  
> 阶段边界：完成结构化编辑与可靠来源回溯，不扩展为复杂项目管理系统。

## 1. 当前问题

当前后端已经支持 Research Idea 的创建、更新、状态流转、删除和从 RAG 会话自动生成草稿，但前端列表只提供查看、改状态和删除，用户无法修改标题、研究问题、创新点、方法、标签等结构化字段。

来源追溯也存在两个缺口：

1. 详情页只显示 `Session #ID` 和逗号分隔的论文 ID，不能一键回到原对话或打开论文；
2. 自动草稿的 `relatedPaperIds` 由大模型阅读 `sourcesJson` 后返回，理论上可能漏填、错填或把来源编号当成论文 ID。

## 2. 本阶段目标

1. 在想法列表和详情中增加“编辑”入口，支持修改全部研究内容字段和状态。
2. 保存编辑时保留 `sourceType`、`sourceSessionId`、`sourceMessageId` 等来源元数据，避免编辑正文导致来源丢失。
3. 详情中提供“打开原对话”和“打开关联论文 PDF”操作，并显示论文标题。
4. 后端直接解析聊天消息的真实 `sourcesJson`，去重提取 `paperId`，覆盖模型输出的关联论文字段。
5. 增加前后端自动测试，验证 API、表单归一化和来源 ID 确定性提取。

## 3. 验收标准

- 用户可以从想法列表或详情打开编辑表单，保存后列表、详情和状态统计同步更新。
- 标题为空时前端阻止提交；关联论文 ID 被规范为去重的正整数逗号串。
- RAG 草稿关联论文只来自 `sourcesJson.paperId`，不采信模型猜测的 ID。
- 有来源会话时可以跳回 `/chat?sessionId=...`；有关联论文时可以直接打开后端 PDF 内容接口。
- 前端测试和构建通过，后端 Research Idea 定向测试与全量测试通过。

## 4. 明确不做

- 不增加新的数据库表或迁移；
- 不做多人协作、评论、版本对比、看板拖拽和任务截止日期；
- 不再次调用 LLM 自动润色编辑后的内容；
- 不改变已经结束的 RAG 检索优化和评测计划。

## 5. 阶段 2：手动创建闭环

结构化编辑和来源回溯完成后，复用同一表单增加“新建想法”入口。手动创建固定使用 `sourceType=manual`、默认保存为 `draft`，不伪造来源会话；创建后刷新列表和状态统计。该阶段只接通后端已有的创建接口，不增加数据库字段。
