# RAG评测结果前端展示规划与完成报告

> 阶段日期：2026-07-16
> 数据来源：`docs/evaluation/reports/final-16-paper-2026-07-16.md`与对应40题原始JSON
> 页面路由：`/evaluation`

## 1. 本阶段目标

检索算法已经达到停止门槛，本阶段不继续调参，而是把固定评测成果产品化展示，使项目演示时可以直接说明：使用什么语料和问题评测、优化前后提升多少、哪些质量护栏通过，以及仍有哪些限制。

范围固定为前端只读展示，不新增后端接口、不读取本地任意文件、不触发Qwen/Qdrant调用，也不把页面设计成实时监控系统。

## 2. 页面信息结构

- 评测范围：16篇论文、40道问题、评测日期、请求成功率。
- 优化前后指标：全库发现Recall/Precision、多粒度使用率、总体Recall/Precision和关键词覆盖率。
- 验收护栏：策略准确率、指定论文范围纯度、reference/noise污染率和人工拒答结果。
- 分类结果：单篇、多篇、全库发现、困难负例和无答案负例。
- 性能说明：平均延迟、完整P95和全库发现P95；明确不把P95包装为提升。
- 已知限制：论文30方法归类、分解题波动、生成延迟和16篇语料规模边界。
- 项目描述：提供经过真实数据约束的简历表述和一键复制入口。

## 3. 数据策略

页面使用版本化只读数据`rag-corpus-16-v1`，数据文件与最终报告同一次提交，避免浏览页面时产生模型费用或因外部服务波动改变展示数字。

未来重新评测时，应同时更新最终原始JSON、评测报告和前端摘要版本，不允许只改页面数字。若后续需要展示多次历史评测，再新增后端评测记录模型和查询接口，当前阶段不提前扩张。
