# 全库论文发现检索优化规划

> 规划版本：2026-07-16 v1
> 适用语料：`rag-corpus-16-v1`（16 篇论文）
> 对照基线：`docs/evaluation/reports/baseline-16-paper-2026-07-16.md`
> 本阶段范围：只优化未指定论文时的 `LIBRARY_DISCOVERY`，不改变单篇全文、指定论文向量问答和多篇混合问答策略。

## 1. 下一阶段要提升什么

下一阶段的核心目标不是让系统生成更多文字，而是让系统在“用户没有指定论文”时，更完整地找出真正相关的论文，并为每篇候选论文提供足够的画像、摘要和原文证据。

当前 16 篇、40 题基线中，单篇理解和多篇比较的目标论文 Recall/Precision 均为 100%，主要短板集中在 10 道全库发现题：

- 全库发现目标论文 Recall 为 82.33%，说明系统会漏掉应该推荐的论文。
- 全库发现 Precision 为 93.00%，总体可用，但个别题会混入主题相近的综述或干扰论文。
- 10 道全库发现题只有 1 道同时使用画像、章节摘要和原文，严格多粒度使用率仅 10%。
- D-LONG-TERM 漏掉 paperId=28 后，最终回答错误判断“没有年度长期预测论文”，证明召回缺失已经影响回答事实正确性。

因此本轮优先级依次为：

1. 提升候选论文覆盖率，减少漏检。
2. 保持推荐精度，避免为了召回而塞入大量弱相关论文。
3. 让画像负责“判断哪篇论文相关”，让章节摘要和原文负责“证明为什么相关”。
4. 不增加新的 LLM 检索调用，控制延迟与外部 API 成本。

## 2. 当前根因

现有 `LIBRARY_DISCOVERY` 会对三路改写查询执行 Qdrant dense 检索，再加入 BM25，并把 `PAPER_PROFILE`、`SECTION_SUMMARY`、`RAW_CHUNK` 放在同一个结果池中做块级 RRF，最后直接截取 `topK`。

这带来三个问题：

1. **不同粒度数量失衡**：当前 Qdrant 中有 16 个画像、1,327 个章节摘要和 1,579 个原文块，画像只有每篇 1 个，在共享 `topK` 中天然处于劣势。
2. **同一论文重复占位**：一篇高相关论文的多个章节块可以占据多个位置，导致其他相关论文没有机会进入最终上下文。
3. **论文聚合发生太晚**：`PaperDiscoveryService` 目前在 LLM 已经回答之后才按 sources 生成推荐卡片，它只能展示已有命中，不能补回检索阶段遗漏的论文。

结论：下一轮必须把“找候选论文”和“找回答证据”分开，先以 `paperId` 为单位决定覆盖哪些论文，再为候选论文补充证据。

## 3. 目标指标与不可退化指标

使用相同 16 篇语料、40 题、`topK=12`、Qwen 模型和评测脚本，与 2026-07-16 基线直接对比。

### 3.1 必须提升

| 指标 | 当前基线 | 本轮目标 |
| --- | ---: | ---: |
| 全库发现目标论文 Recall | 82.33% | ≥ 90.00% |
| 全库发现目标论文 Precision | 93.00% | ≥ 90.00% |
| 严格多粒度使用率 | 10.00% | ≥ 50.00% |
| D-GRAPH 召回 | 2/5 | ≥ 4/5 |
| D-DECOMPOSITION 召回 | 4/6 | ≥ 5/6，并尽量排除综述 29 |
| D-STATISTICAL 召回 | 2/3 | 3/3 |
| D-LONG-TERM 召回 | 1/2 | 2/2 |

### 3.2 必须保持

| 指标 | 最低要求 |
| --- | ---: |
| 策略准确率 | 100% |
| 指定论文范围纯度 | 100% |
| reference/noise 污染率 | 0% |
| 无答案拒答准确率 | 100% |
| 单篇与多篇目标论文 Recall/Precision | 100% |
| P95 延迟 | ≤ 34.947 秒；若略有波动，必须说明原因且不得增加新的 LLM 调用 |

注意：多粒度使用率不是越高越好。目标是让不同粒度各司其职，而不是强制每个回答机械地塞入三类 source。

## 4. 计划采用的检索链路

### 4.1 分类型候选召回

保留现有 Query Rewrite/HyDE 和 BM25 能力，但 Qdrant dense 检索拆为三个独立通道：

- 画像通道：检索 `PAPER_PROFILE`，主要用于发现候选论文。
- 摘要通道：检索 `SECTION_SUMMARY`，用于判断方法、实验、结论等章节相关性。
- 原文通道：检索 `RAW_CHUNK`，用于精确术语、公式、模型名称和原始证据。
- BM25 通道：继续检索原文关键词，补足专有名词和缩写匹配。

每个通道独立保留候选，避免 16 个画像直接与 2,906 个摘要/原文点竞争同一个 `topK`。

### 4.2 paperId 级聚合重排

把各通道结果先聚合到论文级，再计算论文候选分数。第一版采用可解释、可测试的确定性规则，不新增 LLM 重排：

- 画像命中分：论文整体主题是否匹配。
- 最佳章节摘要分：最相关章节是否支持问题。
- 最佳原文/BM25 分：是否存在直接术语证据。
- 多路覆盖分：同一论文被不同查询或不同粒度共同命中时加分。
- 重复收益衰减：同一论文命中很多相似块时，不按块数线性加分，避免单篇论文霸占候选池。

所有权重先做配置常量，并用单元测试固定排序行为；不能直接凭主观反复调参，必须根据定向失败题和完整基线结果调整。

### 4.3 论文覆盖配额

在最终 `topK=12` 的证据预算内，先确定候选论文列表，再控制每篇论文可占用的 source 数量：

- 每篇候选论文至少保留 1 条能够说明相关性的证据。
- 单篇论文默认限制高分证据数量，防止多个相似章节块挤掉其他论文。
- 候选不足时允许剩余名额回流给高分论文，不机械浪费上下文。
- 配额只作用于 `LIBRARY_DISCOVERY`，不影响用户明确选择论文后的精读问答。

### 4.4 候选确定后的证据补全

候选 paperId 确定后，再从已有召回结果中为其选择画像、最相关章节摘要和原文块。若已有结果证据不足，再按候选 paperId 做带范围过滤的 Qdrant 补查。

画像只用于论文级概览，不单独作为关键事实的唯一依据；最终回答中的具体方法、实验结论和数字应优先由章节摘要或原文支持。

## 5. 预计修改范围

### 后端核心代码

- `QdrantService`：复用现有 `contentType` 过滤能力，必要时补充更清晰的分类型检索入口；不迁移 collection，不重新生成向量。
- `RagRetrievalServiceImpl`：把 `LIBRARY_DISCOVERY` 的共享结果池改为分类型通道、论文级聚合和证据配额；`VECTOR_RAG` 保持原逻辑。
- `PaperDiscoveryServiceImpl`：将论文聚合能力前移并扩展为可用于检索决策的排序结果，避免只在回答结束后生成展示卡片。
- `RagChatServiceImpl`：使用优化后的 discovery sources 构造 prompt；保持现有 API 返回结构兼容。
- 配置文件：只有确认权重需要外部配置时才新增 `rag.discovery.*` 配置，第一版避免过度配置化。

### 测试与评测

- `RagRetrievalServiceImplTest`：覆盖三类通道隔离、范围过滤、去重和最终 source 配额。
- `PaperDiscoveryServiceImplTest`：覆盖多路得分聚合、重复收益衰减、稳定排序和候选论文覆盖。
- 现有 40 题评测继续保留原指标，并新增“推荐论文集合”与“source 论文集合”分开统计，避免 D-PV/H-PV 这类“source 有干扰但最终推荐正确”被混为一个指标。

第一轮不要求修改前端。现有 `paperRelevance` 卡片继续使用后端排序结果即可。

## 6. 实施阶段与每阶段产物

### 阶段 1：分类型检索与论文聚合基础（已完成，2026-07-16）

- 实现画像、摘要、原文、BM25 独立候选通道。
- 建立 paperId 级候选得分模型和确定性排序。
- 增加单元测试，确认指定论文检索路径完全不受影响。
- 完成后更新 `docs/status/current.md`，记录代码范围、测试数量和已知问题。

实际完成结果：

- 每条改写查询只调用一次 Embedding，并复用查询向量分别检索 `PAPER_PROFILE`、`SECTION_SUMMARY`、`RAW_CHUNK`，避免三种内容类型造成 Embedding 调用数增加三倍。
- 三类候选池分别执行 RRF；BM25 归入原文候选池，保持关键词召回能力。
- 新增论文级确定性排序：按内容类型独立归一化，画像/摘要/原文权重分别为 0.40/0.35/0.25，第二条同类证据按 0.25 衰减，多粒度共同命中增加覆盖分。
- 最终上下文先覆盖最多 6 篇候选论文，再按论文轮询补充第二、第三条证据；这一步建立基础覆盖，精细内容类型配额仍属于阶段 2。
- 定向测试 18 项全部通过；后端全量测试 130 项通过、0 失败、0 错误、1 项真实外部对比测试按条件跳过。
- 本阶段尚未运行真实 discovery 用例，不能提前宣称 Recall/Precision 已提升；真实量化留在后端重启后的阶段 2 定向验收和阶段 3 完整评测。

后端重启后的补充定向结果：6道重点题source宏平均Recall从70.56%提升到94.45%，5道discovery严格三粒度使用率从0%提升到80%；但source宏平均Precision从75.83%下降到44.45%，D-DECOMPOSITION Recall仍为66.67%。因此阶段1只确认“覆盖改善”，不能作为最终优化完成值；阶段2必须增加动态候选截止和候选后的分类型证据配额。详细结果见 `docs/evaluation/reports/discovery-stage1-2026-07-16.md`。

### 阶段 2：动态候选截止与证据补全（代码已完成，待真实验收）

- 实现每篇论文的 source 上限、最低证据覆盖和剩余配额回流。
- 保证候选画像不会取代原文事实证据。
- 用 6 个重点用例定向验证：D-GRAPH、D-DECOMPOSITION、D-STATISTICAL、D-LONG-TERM、D-PV、H-PV。
- 完成后更新 `docs/status/current.md`，记录定向题优化前后差异。

实际代码完成情况：

- 保留最多8篇宽候选用于论文级排序，进入上下文前再根据问题表达和相对分数动态截止：唯一/单目标问题最多2至3篇，双目标问题至少2篇，列举型问题最多6篇。
- 论文级得分加入明确查询术语覆盖加分；术语只在章节摘要和原文证据中计算，避免画像中的泛化描述获得等价加分。
- 当用户询问原创方法且未询问综述时，对标题中明确包含review/survey/综述的论文做可解释降权；用户主动询问综述时不降权。
- 每篇入选候选先分配1条paper_profile，再分配1条section_summary或raw_chunk事实证据，剩余topK预算按论文轮询回流。
- paperRelevance展示上限从5篇调整为6篇；评测脚本新增推荐卡片论文Recall/Precision，与source论文指标分开保存。
- 阶段2定向自动测试22项通过；后端全量133项通过、0失败、0错误、1项真实外部测试按条件跳过。
- 尚未重启IDEA后端运行6道真实问题，因此Precision恢复、D-GRAPH最终5/5和D-DECOMPOSITION至少5/6仍属于待验收目标，不能当作已实现指标。

阶段2首次真实6题结果：source Recall 97.22%、Precision 84.72%，5道discovery Precision 91.67%，严格三粒度使用率60%，平均/P95延迟15.146/19.266秒；D-DECOMPOSITION最终达到5/6，D-PV只保留38。唯一未通过的关键答案指标是D-GRAPH仍错误排除已召回的paperId=30。事实审计确认30确实构建k近邻图和25站点图结构，失败原因是候选内事实证据选择不准确；已增加查询术语优先证据选择、图证据扩展词、唯一问题单候选上限和更强综述降权，待重启后做3题最终复测。详细见 `docs/evaluation/reports/discovery-stage2-2026-07-16.md`。

第一次3题边界复测表明“唯一问题单候选硬上限”本身过于激进：H-PV-DISTRACTOR在正确论文38之前截取了综合分更高的通用风速论文19。现已改为唯一问题按明确术语覆盖率优先选1篇；同时约束发现prompt严格区分来源编号与论文ID，并按证据识别图结构建模。自动回归已通过，待后端再次重启后复测3题。完整40题仍不得提前执行或宣告完成。

第二次3题边界复测确认光伏唯一答案和来源ID语义已修复；D-GRAPH剩余失败进一步定位为同一论文内“相关工作背景摘要”压过“自身直接方法摘要”。现已在事实证据排序中加入背景内容降级，优先保留包含本文提出、构图、邻接矩阵等直接方法标记的证据。该修正待重启后单题验证，未通过前继续暂停完整40题。

阶段3最终决策：用户要求避免无限优化后，取消10道discovery连续3轮，仅执行一次完整40题终验。最终全库发现Recall/Precision为96.67%/91.67%，严格三粒度使用率70%，策略/范围纯度100%、噪声污染0%，达到停止门槛。本优化阶段正式结束；D-GRAPH对paperId=30的生成归类分歧与D-DECOMPOSITION单轮波动作为已知限制，不再继续添加规则。完整结果见`docs/evaluation/reports/final-16-paper-2026-07-16.md`。

## 7. 验收规则

本阶段只有同时满足以下条件才算完成：

1. 全库发现 Recall 达到至少 90%，Precision 不低于 90%。
2. D-LONG-TERM 不再因漏掉 paperId=28 给出错误的“没有相关论文”结论。
3. 单篇、多篇、范围隔离、噪声过滤和拒答指标不退化。
4. 没有新增 LLM 检索调用，Qdrant/MySQL 数据无需重建。
5. 自动化测试、定向真实问题和完整 40 题结果均已保存，任何提升都有可复查的原始数据。

若 Recall 达标但 Precision 跌破 90%，或 P95 显著上升，则不能宣告阶段完成，需要调整候选阈值、每篇配额或证据补查范围后重新评测。

## 8. 风险与控制方式

- **召回增加导致精度下降**：通过论文级最低分、每篇配额和完整 Precision 门槛控制。
- **画像包含生成性概括**：画像只辅助候选排序，具体事实必须尽量由摘要或原文支撑。
- **综述论文挤压原创论文**：先观察 paperId 聚合是否已改善；只有仍稳定出现时，才增加“综述/原创”可解释规则，避免一开始引入脆弱启发式。
- **并行检索增加延迟**：分类型 Qdrant 查询可以并行执行，不新增 LLM 调用；以 P95 基线作为硬约束。
- **指标口径混淆**：后续同时报告 source 论文、推荐卡片论文和人工抽查的回答论文，旧指标保留以保证历史可比性。

## 9. 本阶段结束后可用于项目描述的内容

只有真实达到验收门槛后，才可以在简历中写成：

> 针对多粒度向量共享 TopK 导致的论文漏召回问题，设计分类型候选召回、paperId 级聚合重排与证据覆盖配额；在固定 16 篇、40 题真实 RAG 回归集上，将全库论文发现 Recall 从 82.33% 提升至实际复测值，并保持 Precision、范围隔离与拒答指标不退化。

其中“实际复测值”必须使用优化后的真实报告填写，规划目标不能当作最终成果。
