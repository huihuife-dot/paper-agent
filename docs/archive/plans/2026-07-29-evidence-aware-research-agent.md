# 科研证据驱动 Agent 升级计划

> 计划日期：2026-07-29
> 计划状态：已完成并归档
> 影响仓库：MyAgent、独立 Research Engineering Agent
> 核心目标：让 MyAgent 新增的多模态复现证据不只“进入提示词”，而是确定性地影响本地 Agent 的准备度判断、执行边界、代码决策和长期交接。

## 1. 背景

MyAgent 已经能够从正文、图、表、公式和算法块中构建带来源的复现事实，并通过 `ReproductionSpec` 和 Agent Context v2 区分可信事实、待复核事实、模型推断、冲突、缺失信息和安全默认值。

独立 Agent 当前已经兼容并保存 v2 协议，也会在提示词和 handoff 中要求模型区分事实类别；但主要执行方式仍是把任务包整体交给模型自行理解，尚未形成以下确定性机制：

1. `READY`、`PARTIAL`、`NEEDS_REVIEW`、`NOT_READY` 对执行流程的影响不够明确；
2. 完整规格直接进入提示词，存在重复信息、上下文膨胀和论文内容被当成指令的风险；
3. 交接能记录事实分类数量，但不能回答“哪项代码决策依据了哪条论文事实”；
4. Idea 上下文中的关联论文仍以摘要级证据为主，没有充分利用可信复现事实；
5. 长期任务继续执行时，尚未形成论文证据版本变化的差异检查。

## 2. 目标

本计划完成后，两端应形成以下闭环：

```text
MyAgent 多模态资产与复现事实
→ ReproductionSpec / Agent Context v2
→ 本地类型校验与准备度决策
→ 紧凑证据索引和按需读取
→ 证据约束下的代码修改
→ evidence-to-code 结构化追踪
→ 基础运行检查与 handoff
→ 安全摘要和证据版本同步回 MyAgent
→ 后续继续任务时检查证据变化
```

## 3. 非目标

- 不在本地 Agent 中重复实现 PDF、图表、公式解析或 Qwen-VL 分析；
- 不自动选择论文中的冲突参数；
- 不自动下载数据、训练模型、调参或复现论文指标；
- 不把本地绝对路径、源代码或密钥同步到 MyAgent；
- 不用未经真实评测的数字包装效果。

## 4. 分阶段实施

### 阶段 A：类型化证据协议与准备度决策

- 在本地 Agent 中建立 `ReproductionSpec`、事实、冲突和准备度报告的类型模型；
- 校验协议版本、论文 ID、来源版本、事实来源和嵌套字段；
- 将 `READY`、`PARTIAL`、`NEEDS_REVIEW`、`NOT_READY` 转换为确定性的本地执行策略；
- `NEEDS_REVIEW` 只阻塞依赖冲突的决策，不阻塞无关代码骨架；
- 明确固定请求 Agent Context v2，避免服务端默认版本变化导致行为漂移。

验收：错误规格被拒绝；四种准备状态均有聚焦测试；执行提示能明确当前允许事项和阻塞项。

### 阶段 B：紧凑证据索引、按需读取与提示词安全边界

- 保存完整上下文快照，同时生成适合模型首轮使用的紧凑证据索引；
- 去除任务包中重复的完整 `ReproductionSpec`，仅保留准备度摘要、关键可信事实、冲突、缺口和安全默认值；
- 提供只读证据查询工具，按 fact ID 或关键词读取完整事实和来源；
- 明确论文、视觉分析和检索内容都是不可信数据，不得作为工具指令执行。

验收：首轮提示词不再携带重复完整规格；工具只能读取当前论文证据；模型推断不会被查询为可信事实。

### 阶段 C：证据到代码追踪与系统回写

- 增加结构化实现决策记录，区分 `EVIDENCE_BACKED`、`SAFE_DEFAULT` 和 `BLOCKED`；
- 可信实现必须引用有效 fact ID，安全默认值必须记录原因，冲突事实不能被静默选用；
- handoff 增加证据版本、准备度、实现决策和目标文件；
- MyAgent 项目活动摘要增加准备状态、证据版本和追踪文件索引，不上传本地源代码。

验收：机器可读 handoff 能从实现决策追溯到论文页码和来源；非法 fact ID 或冲突选择被拒绝。

### 阶段 D：Idea 关联论文证据增强

- MyAgent 的 Idea improvement context 为关联论文选择与 Idea 方法相关的可信事实和关键原文；
- 明确三类信息的职责：Idea 定义目标、RepositoryBaseline 定义当前代码事实、论文证据支持方法细节；
- 本地任务包保留证据来源层级，避免把关联论文内容误当成用户目标。

验收：Idea 接口保持旧字段兼容；关联论文有规格时返回可信事实，没有规格时安全降级为摘要证据。

### 阶段 E：长期任务的证据版本变化

- 为论文上下文补充与 Idea 类似的快照比较；
- 继续任务前比较 `sourceRevision` 和语义哈希；
- 生成新增、删除、状态升级、冲突和缺失项变化摘要；
- 只有变化影响既有决策时才要求关键人工确认。

验收：相同版本不重复处理；不同版本生成可读差异；旧快照仍不可变且可追溯。

### 阶段 F：双项目验证与文档收口

- 本地 Agent 完成聚焦测试和全量回归；
- MyAgent 完成 Research Engineering 服务测试、后端相关回归和文档链接检查；
- 使用已存在的 Paper 13 `PARTIAL` 与 Paper 38 `NEEDS_REVIEW` 样例验证策略差异；
- 有条件时调用已配置模型完成真实短链路，原始结果单独保存，不把基础运行等同于科研实验；
- 更新两个项目的架构、当前状态、自主改进、项目介绍和面试文档。

## 5. 风险与处理

| 风险 | 处理 |
| --- | --- |
| v2 规格较大导致提示词膨胀 | 完整规格落盘，首轮只注入紧凑索引，细节按需读取 |
| 论文文本包含类似命令的内容 | 数据和指令分区，证据工具只返回结构化只读内容 |
| 冲突导致整个任务无法推进 | 只阻塞依赖冲突的决策，其余任务继续 |
| MyAgent 暂时离线 | 本地快照仍可继续；同步失败保留待重试记录 |
| 新协议破坏旧项目 | v2 增量适配并保留 v1 读取，新增字段保持向后兼容 |
| Idea 关联论文过多 | 按 Idea 相关性和事实类型限额选择，不全量注入 |

## 7. 完成结果

- 本地 Agent 固定协商 Context v2，并保留 v1 历史快照兼容；
- `NOT_READY` 在模型调用前暂停，其他状态映射为明确的受限策略；
- 完整规格落盘，首轮只携带紧凑索引，细节通过只读工具按需查询；
- 每轮生成 evidence-to-code trace，并将准备状态、策略和决策计数安全同步到 MyAgent；
- Idea 上下文加入按 Idea 相关性筛选的关联论文可信事实与关键原文；
- 长期论文任务能够比较证据版本，并判断变化是否影响既有代码决策；
- 验证记录见[科研证据驱动 Agent 双端联调报告](../../evaluation/reports/evidence-aware-agent-integration-2026-07-29.md)。
