# RAG 分段耗时可观测性计划

> 状态：已完成  
> 日期：2026-07-16

## 目标

在不改变召回排序、不增加任何模型调用的前提下，记录一次 RAG 问答各阶段耗时，并在前端和评测原始结果中展示，使后续性能决策基于真实瓶颈数据。

## 观测阶段

- 策略选择；
- Query Rewrite；
- Embedding；
- Qdrant 向量搜索；
- Qdrant 结果解析与 MySQL 来源回查；
- BM25；
- RRF / 论文聚合排序；
- 上下文和 Prompt 构造；
- LLM 完整生成；
- 对话历史保存；
- Idea 建议、论文卡片等后处理；
- 请求总耗时和未归类耗时。

## 实施边界

- 使用请求线程内的轻量计时上下文，不写数据库、不新增远程调用；
- 保持 `POST /api/rag/chat` 兼容，只新增 `timing` 响应字段；
- 前端增加折叠式执行详情，不改变回答和引用布局；
- 评测脚本保存单题 timing，并按策略聚合主要阶段占比；
- 不在本阶段实现 SSE 流式输出、缓存或模型参数优化。

## 验收标准

1. 四种上下文策略均返回非空 timing 和总耗时；
2. Dense 路径能区分 Embedding、Qdrant 和来源回查；
3. 前端能够显示主要阶段、总耗时和占比；
4. 原有后端、前端测试通过，RAG 策略与来源不变化；
5. 使用单篇、多篇、全库代表题形成真实分段性能报告；
6. 根据数据只给出一个后续性能方向，不在本轮直接继续优化。

## 完成结论

全部验收项已完成。三类真实用例均返回分段 timing，前端和评测脚本均可展示/聚合；三题主要瓶颈全部为 LLM 生成。量化结果见[分段耗时观测报告](../../evaluation/reports/rag-performance-observability-2026-07-16.md)。
