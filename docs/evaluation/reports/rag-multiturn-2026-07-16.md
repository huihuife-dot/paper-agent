# 历史感知多轮 RAG 评测报告

> 评测日期：2026-07-16  
> 语料版本：`rag-corpus-16-v1`（16 篇已画像并向量化论文）  
> 原始结果：`test/results/rag-multiturn-2026-07-16.json`

## 1. 评测目标

本轮验证的不是普通单轮召回，而是同一会话中的追问能否利用最近对话恢复省略信息，再沿用正确的 RAG 路由检索。实现只读取最近 6 条消息（约 3 轮），不引入长期记忆或对话向量库。

## 2. 评测方法

脚本 `test/run-rag-multiturn-evaluation.mjs` 连接本地真实 Spring Boot、MySQL、Qdrant 和 Qwen 服务。每个场景先发送一条完整问题建立会话，再携带返回的 `sessionId` 发送依赖上下文的追问，总计执行 6 次 SSE 问答。

| 场景 | 追问 | 预期验证 |
| --- | --- | --- |
| 单篇代词 | `它有什么局限？` | 恢复论文 13 和具体方法，继续走单篇全文 |
| 多篇比较 | `二者在空间建模方面有什么区别？` | 恢复论文 13、15，继续走多篇混合 RAG |
| 全库指代 | `其中哪一篇更强调图神经网络？` | 保留上一轮候选语境，继续走全库发现 |

量化指标：

- 执行成功率：两轮请求均成功完成的场景比例；
- 改写率：追问的 `retrievalQuestion` 与用户原问题不同的比例；
- 语义锚点覆盖率：实际检索问题包含预期论文 ID 或主题词的比例；
- 策略准确率：实际 `contextStrategy` 与预期路由一致的比例；
- 预期论文召回率：最终来源中命中的预期论文数 / 预期论文数；
- 首段时间与完整时间：从追问请求开始到首个正文片段、完整响应结束的耗时。

## 4. 结论与边界

本阶段证明了三条代表性链路能正确恢复对话指代，并且改写后没有破坏既有路由和目标论文召回。用户原始问题仍保存到历史，独立检索问题只用于检索与回答，前端执行详情可以同时展示两者，便于解释和排错。

本结果是 16 篇语料、3 个连续追问场景的小规模功能回归基线，不代表大规模文献库或开放域多轮问答的通用准确率。平均完整耗时还受到回答长度和外部模型波动影响；本阶段停止继续堆规则，未来只有在真实使用出现失败案例或语料扩展到 50 篇以上时再扩充多轮评测集。

## 5. 复现

确保 IDEA 后端、MySQL、Qdrant 和模型 API 可用，在项目根目录执行：

```powershell
node test/run-rag-multiturn-evaluation.mjs
```
