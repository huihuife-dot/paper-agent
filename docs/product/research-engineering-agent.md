# Research Engineering Agent 功能说明

> 该功能基于独立的 Claude Code / Research Engineering Agent 项目接入。MyAgent 负责科研上下文、网页入口和安全项目索引，本地 Agent 项目负责代码执行与完整交接记录。

## 功能定位

Research Engineering Agent 是 MyAgent 的本地代码落地能力。它把系统中已管理的文献和 Research Idea 转换为有边界的本地代码任务，而不是一个泛用的“什么都做”的聊天 Agent。

## 两个用户入口

| 用户在 MyAgent 中选择 | 点击后交给本地 Agent 的任务 | 产物 |
| --- | --- | --- |
| 单篇文献 | 基于该文献做可运行的最小代码复现 | 独立工作目录中的代码、入口、基础检查记录和交接摘要 |
| Research Idea | 在用户选择的已有代码目录中实现一次聚焦改进 | 受目录边界保护的代码变更、基础检查记录和交接摘要 |

产品界面中的“按 Idea 复现”应理解为“按 Idea 改进已有代码”。论文可以在新隔离目录中做最小复现；Idea 没有天然可复现的代码实体，因此必须先选择一个现有仓库作为改进基线。

## 对用户的承诺

- 用户不必手工把论文摘要、Idea、聊天内容复制给通用模型。
- 任务不是一次性的：本地工作目录保留上下文快照、版本摘要和交接记录，后续可以在同一个 CLI 窗口继续改进。
- Agent 的目标是交付代码和基本可运行性，而不是代替用户跑科研实验、解释最终效果或得出论文结论。

## 为什么不是直接把文本交给大模型

MyAgent 在点击操作时输出统一的结构化任务包。任务包说明目标、实施步骤、可追溯证据、已知参数、缺失信息、代码范围和基础验收条件。这样 Agent 知道哪些内容来自文献/Idea，哪些只是安全假设，哪些信息不足必须说明。

论文模式会先生成 `ReproductionSpec`。界面直接显示准备状态、关键项覆盖率、来源完整率，以及可信事实、待复核、模型推断、冲突和缺失数量。用户还能在启动前预览将交给 Agent 的关键原文与可信事实。冲突、低置信度内容和 `MODEL_INFERRED` 不会自动变成实现参数。

对于 Idea 模式，本地端还会根据用户选择的目录补上允许修改路径、禁止修改路径和已有检查命令。该信息只保留在用户电脑，不上传到 MyAgent 服务端。

Idea 关联论文不再只提供摘要。系统会根据 Idea 标题、研究问题、方法和标签，限量选择相关论文中的可信复现事实与关键原文。Agent 按“**Idea 决定改什么、现有仓库决定现在是什么、论文证据辅助决定方法细节**”的顺序处理，避免论文材料反过来篡改用户目标。

首次选择 Idea 代码目录时，本地 Agent 会自动识别常见 Python、Maven、Node 工程线索，生成仓库基线；每轮结束会生成可读摘要和结构化交接文件。失败或达到安全轮数时同样保留交接与下一步，不会丢失已经完成的代码工作。

## 使用边界

- 文献复现只针对用户选中的单篇文献；不会混入无关的全库聊天历史。
- Idea 改进只修改用户选择目录中允许的路径；越界文件写入会被本地权限机制拒绝。
- 基础检查仅用于确认代码能编译、导入或短暂启动，不包含下载依赖、长时间训练、实验、调参、Git 合并或推送。
- 用户仍负责数据准备、完整测试、实验设计、指标评测及研究结论。

## 完成后的记录

一次复现或 Idea 改进完成后，不会只在 CLI 中显示一次结果就消失：本地工作目录会保存完整的上下文快照、每轮交接摘要、版本检查点和事件日志；MyAgent 的“复现项目”记录会保存对应的项目状态和活动历史。两边使用项目 ID、文献/Idea 来源 ID、会话 ID 和版本号关联。

论文任务还会生成 evidence-to-code trace：可信实现引用事实 ID 和来源，安全默认值记录选择原因，缺失或冲突记录为阻塞。MyAgent 项目页只展示准备状态、策略和三类决策数量；完整 trace 留在本地，避免上传代码和绝对路径。

如果某一轮达到 Agent 的安全轮数上限，系统会记录为“等待继续”，而不是误写成“已完成”。用户可以在原本地工作目录继续发起较小的后续要求，历史记录仍会接在同一个项目下。

系统端只保存相对摘要路径、状态和摘要等安全信息，不保存用户电脑的绝对目录、源代码或密钥。这样既能在网页中追踪“做过什么、做到第几轮”，又不会把本地代码隐私带到线上系统。
